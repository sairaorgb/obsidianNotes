#### Intro

- A **host environment** for JavaScript is the runtime where the code is executed. It provides objects and functions that JavaScript can interact with in addition to the core. It could be a web browser, web server, another host or a coffee machine if it can run js.

- The Document Object Model, or DOM for short, represents all page content as objects that can be modified.
- The Browser Object Model (BOM) represents additional objects provided by the browser (host environment) for working with everything except the document.

- Browser = V8 (or other JS engine) + DOM + BOM + Web APIs → for web pages.
- Node.js = V8 + Node APIs (fs, http, etc.) → for server-side work, no DOM/BOM.

#### DOM tree

- There are 12 node types. In practice we usually work with 4 of them:
	- document – the “entry point” into DOM.
	- element nodes – HTML-tags, the tree building blocks.
	- text nodes – contain text.
	- comments – sometimes we can put information there, it won’t be shown, but JS can read it from the DOM.
	
- Spaces and newlines are totally valid characters, like letters and digits. They form text nodes and become a part of the DOM.
- If the browser encounters malformed HTML like missing head tag or closing tags, it automatically corrects it when making the DOM.
- An interesting “special case” is tables. By DOM specification they must have < tbody> tag, but HTML text may omit it. Then the browser creates < tbody> in the DOM automatically.

# DOM (Document Object Model) in JavaScript

## What is DOM

- A programming interface representing an HTML document as a tree of nodes.    
- Provides access and methods for reading and manipulating structure, style, and content.
- JS interacts with the DOM via `document` and `window` objects.

## Attributes vs Properties

- **Attributes**: Defined in the original HTML (static). Example: `<input value="Hello">`.    
- **Properties**: Current "live" state in JS (changes as the user interacts).
- `getAttribute()` reads the original HTML attribute.
- `element.property` (e.g., `input.value`) gives current state.
- `setAttribute()` modifies both the DOM element and its HTML serialization in memory, but not the source `.html` file on disk.
- Reloading the page resets JS state to initial HTML.

## ClassList

- `element.classList` provides methods to manipulate classes:
    - `add()`, `remove()`, `toggle()`, `contains()`, `replace()`.
- Classes here are just CSS class names; Tailwind utilities also work since they are class-based.

## innerHTML vs textContent

- **innerHTML**: Reads/writes HTML markup inside an element. Unsafe with user input (risk of XSS).
- **textContent**: Reads/writes only text, without parsing HTML.

## Querying Elements

- `document.getElementById("id")`
- `document.getElementsByClassName("class")`
- `document.getElementsByTagName("tag")`
- `document.querySelector("selector")` (first match)
- `document.querySelectorAll("selector")` (all matches, NodeList)

## Creating & Modifying Nodes

- `document.createElement("tag")` → creates an element.
- `parent.append(child)` → add node to the end.
- `parent.prepend(child)` → add node to the beginning.
- `parent.insertBefore(newNode, referenceNode)` → insert at specific position.
- `node.remove()` → remove element.
- `node.cloneNode(deep)` → copy a node (`deep=true` copies children too).

## Traversing DOM

- `element.parentNode` → parent element.
- `element.children` → HTMLCollection of child elements.
- `element.firstElementChild` / `lastElementChild`.
- `element.nextElementSibling` / `previousElementSibling`.

---

## Styles

- Inline styles: `element.style.property = "value"`.
- Full computed style: `window.getComputedStyle(element)` (read-only snapshot).

## DOM Events

- Events represent interactions or changes (e.g., `click`, `input`, `load`).
- Attach handlers with `element.addEventListener(event, handler)`.

### Event Object

- Provides details: `type`, `target`, `currentTarget`, mouse/keyboard info, etc.
### Event Flow

- Capturing phase: root → target.
- Bubbling phase: target → root.
- Listeners run in bubbling by default, capturing enabled with third param `true`.
- `event.stopPropagation()` prevents further propagation.

### Event Delegation

- Place one listener on a parent element, handle events for children via `event.target`. Useful for dynamic elements.

### Controlling Events

- `event.preventDefault()` cancels default browser action.
- `event.stopPropagation()` stops bubbling/capturing further.

### Common Events

- Mouse: `click`, `dblclick`, `mouseenter`, `mouseleave`, `mousemove`.
- Keyboard: `keydown`, `keyup`.
- Form: `input`, `change`, `submit`, `focus`, `blur`.
- Window: `load`, `resize`, `scroll`, `beforeunload`.

## FormData API

- `new FormData(formElement)` creates key-value pairs of form data.
- Useful for AJAX/Fetch submissions.
- Methods: `get(key)`, `set(key, value)`, `append(key, value)`, `delete(key)`.


## DOM Events
- Events are signals that something happened (click, input, keydown).
- Event object is passed to handlers with details about the event.

### Event Flow
- Capturing: event travels from root → target.
- Target: event executes on the element clicked/interacted.
- Bubbling: event travels from target → root.
- By default, browsers use bubbling phase for handlers.

### Event Delegation
- Attach one listener on a parent instead of multiple children.
- Use `e.target` to detect which child triggered the event.
- More efficient for dynamic elements.

### Event Object Properties
- e.target: the element that triggered the event.
- e.currentTarget: the element the listener is attached to.
- e.stopPropagation(): stops event from bubbling up.
- e.stopImmediatePropagation(): stops bubbling and cancels other handlers on the same element.
- e.preventDefault(): prevents default browser action (e.g. form submit, link navigation).

### Adding Listeners
- element.addEventListener(type, handler, useCapture)
- useCapture (optional boolean): true means listen in capturing phase.
- Multiple listeners can exist on the same element for the same event.
