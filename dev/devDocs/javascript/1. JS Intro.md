#### Variables

- A variable is a “named storage” for data.To create a variable in JavaScript, use the `let` keyword.
``` js 
// commas enable to declare multiple vars on diff lines
let user = 'John',
age = 25,
message = 'Hello';
```
- The name must contain only letters, digits, or the symbols $ and _.
- To declare a constant (unchanging) variable, use const instead of let. A loose convention is to use capital case for compile time constants and small case for run time constants. 


- **`var`** → legacy, function-scoped, hoisted weirdly.
- **`let`** → block-scoped, no redeclaration, lives in the TDZ (Temporal Dead Zone).
- **`const`** → same as `let` in scoping, but binding is immutable (not the value itself).

- function scoped variables are available throught the function `{}`even if they are decalred inside a block like loops but block scoped ones only are available inside blocks`()`. 
- Hoisting is a mechanism where all variables are moved to top at compile time. But var is initialized with undefined value and let const live in TDZ where they are unavailable till the intialization happens.
- var adds properties to `globalThis`/window .

- **Hoisting** During the compile phase js moves declaration not executions to the top of their scope. 
- Creation phase (memory setup)
    - JS allocates memory for vars & functions.
    - Vars with `var` → `undefined`.
    - `let/const` → reserved but uninitialized (TDZ).
    - Functions → full definition stored.
- Execution phase
    - Code runs line by line.
    - Assignments & logic happen here.
    - access before declaration causes var to output undefined , let/const to reference error and functions work fine tho. class declaration behave like let too. 
- 
``` js
// `Shadowing` causes 2nd declaration to get hoisted in fun level scope thereby making x to be undefined
var x = 10;
function test() {
  console.log(x); // undefined (inner var is hoisted!)
  var x = 20;
}
test();
```


#### Data types


There are 8 basic data types in JavaScript.

| Type          | Example                               | Notes                              |
| ------------- | ------------------------------------- | ---------------------------------- |
| **Number**    | `42`, `3.14`, `-0`, `NaN`, `Infinity` | Includes `NaN`, `Infinity`, etc.   |
| **String**    | `"hello"`, `'world'`                  | Sequence of characters             |
| **Boolean**   | `true`, `false`                       | Logical values                     |
| **Undefined** | `undefined`                           | Variable declared but not assigned |
| **Null**      | `null`                                | Explicit "no value"                |
| **BigInt**    | `123n`, `9007199254740991n`           | For very large integers            |
| **Symbol**    | `Symbol('desc')`                      | Unique identifiers                 |

- Special Values

| Value       | Type        | Description                                      |
| ----------- | ----------- | ------------------------------------------------ |
| `undefined` | `undefined` | Variable declared but not initialized            |

- if there’s a NaN somewhere in a mathematical expression, it propagates to the whole result (there’s only one exception to that: NaN ** 0 is 1).
- `number` type cannot safely represent integer values larger than (2^53-1). Beyond which it starts to round them to precision. so BigInt is used. 
- No special char, they are string too. Double and single quote strings are same. But strings with Backticks allow embedding.
- `Number` considers float, int, hexadecimal, binary and exponential as same.

#### Basic operators

- If either operand is a string, + → string concatenation. Else, both operands are coerced to numbers.
- any other operator converts strings to numbers and evaluate even if it's NaN.
``` js 
alert(2 + 2 + '1' ); // "41" and not "221"
alert('1' + 2 + 2); // "122" not '14'

// Unary + Converts non-numbers
alert( +true ); // 1
alert( +"" );   // 0

// chained assignments evaluate from right to left. 
a = b = c = 2 + 2;
```
 - The assignment operator in  x = value writes the value into x and then returns it.
 
 - **Postfix and Prefix** - prefix returns first and evaluates whereas suffix evaluates and then returns .. They have precedence same as arithmetic operators.
 ``` js 
Expression order matters:
let a = 1;
let b = a++ + ++a; // b = 1 + 3 = 4

Array indexing:
let arr = [10, 20]; let i = 0;
arr[i++] → 10, i = 1

Function arguments:
let x = 1;
func(x++, ++x); // Order is left to right, but values may surprise

Condition checks:
let i = 0;
if (i++ === 0) → true, i becomes 1 after

Avoid in complex expressions:
i++ + i++ + i → ❌ unclear, side effects stack
```

- Bitwise operators treat arguments as 32-bit integer numbers and work.

#### Type coercion

- To Number — Happens in math, comparisons
- space characters are trimmed off string. 
``` js 
Number(null)      → 0
Number(undefined) → NaN
Number(true)      → 1
Number(false)     → 0
Number("42")      → 42
Number("  ")      → 0
Number("")        → 0
Number("abc")     → NaN
Number(" \t \n ") → 0
Number([])        → 0
Number([1])       → 1
Number([1,2])     → NaN
Number({})        → NaN
```

- To String — Happens in `+` when one operand is a string.
``` js
String(null)       → "null"
String(undefined)  → "undefined"
String(true)       → "true" 
String(123)        → "123"
String([1,2,3])    → "1,2,3"
String({})         → "[object Object]"
```

##### Coercion table

| Operand Types       | Coercion Behavior                                  |
| ------------------- | -------------------------------------------------- |
| Number == String    | Convert String → Number                            |
| Boolean == Any      | Convert Boolean → Number                           |
| Object == Primitive | Convert Object → Primitive (`valueOf`, `toString`) |
| null == undefined   | `true`                                             |
| NaN == anything     | `false` (even `NaN == NaN`)                        |
| String == Object    | Object → Primitive, then String compared           |


#### Comparisons

- String comparison is made with lexographical analysis with unicode values. pitfall is smaller case have bigger unicode values than upper case. 
- In case of comparison operators If both operands are strings, → string comparison. Otherwise → both coerced to numbers (except undefined).

- `==` does type coercion before comparing unlike `===` . type coercion in js is too erratic and care is needed.
- **Truthy** values are the ones that are logical true and the opposite is **falsey**.

- To Boolean — Happens in conditions (e.g., if(x))
``` js
false, 0, -0, 0n, "", null, undefined, NaN 
// anything except them is truthy

"0" // truthy
```

- A strict equality operator === checks the equality without type conversion.
``` js 
alert( null === undefined ); // false
alert( null == undefined ); // true

// for math and other comparisons except equality
// null becomes 0 and undefined become NaN

alert( null > 0 );  // (1) false
alert( null == 0 ); // (2) false
alert( null >= 0 ); // (3) true

// null only == with undefined by convention. whereas during comparison operators, it is converted to Number (same with undefined)


```


#### More on Operators

- **Terenary operator**  - (boolean) ? (expression) : (expression)
- statement can be of return type or it can be of executional.

- **Logical operator** - Include `||` , `&&` , `!`,`??`
- returns values instead of booleans. 
- Logical OR returns **first truthy** value or **last falsy** one.
- Logical AND returns **first falsy** value or **last truthy** one.
- Logical NOT returns boolean equivalent. 
- `!!` can be used to convert value into its boolean. 
- The precedence of AND `&&` operator is higher than OR `||`.
 
- In a multiple OR statement, evaluation is done from left to right , first truthy value is returned and all other are ignored for evaluation or In case of all being false, last falsey is returned. 

``` js 
alert( firstName || lastName || nickName || "Anonymous"); // SuperCoder

// short circuit evaluation
true || alert("not printed");
false || alert("printed");

// examples
alert( alert(1) || 2 || alert(3) ); // first 1, then 2.
alert( alert(1) && alert(2) ); // 1 and undefined in alert 
alert( null || 2 && 3 || 4 ); //3
```

-  **Nullish coalescing operator** - `??` returns the first argument if it’s not `null/undefined`. Otherwise, the second one.
- `||` checks for first falsy value whereas `??` checks for first defined value; 
``` js 
height = 0 
height || 100; // return 100
height ?? 100; // return 0 
```

#### Loops 

 - break/continue support labels before the loop. A label is the only way for break/continue to escape a nested loop to go to an outer one.
##### Loop helpers


### **1. `forEach` (execution sidekick, no return)**

```js
[1, 2, 3].forEach(x => console.log(x * 2));
```

- Executes a callback for each element.
- **Does not return anything useful** (always `undefined`).
- Great for side effects (logging, pushing to external arrays, DOM manipulation).
- Not chainable.

**Nuance:**

- If you `return` inside, it’s ignored.
- `break`/`continue` don’t exist here—use exceptions to “escape” (ugly hack).

### **2. `map` (transformation wizard)**

```js
const doubled = [1, 2, 3].map(x => x * 2); // [2, 4, 6]
```

- Returns a **new array** with the transformed values.
- Pure function style: input unchanged.
- Chainable

**Nuance:**

- If you forget to `return` in your callback, you’ll end up with `[undefined, undefined...]`.
- Performance-wise, not always faster than a loop (but more expressive).



### **3. `filter` (the gatekeeper)**

```js
const evens = [1, 2, 3, 4].filter(x => x % 2 === 0); // [2, 4]
```

- Returns a new array of elements passing the condition.
- Non-destructive.

**Nuance:**

- Empty condition = empty array.    
- Chainable with `map` and others.

### **4. `reduce` (the philosopher king)**

```js
const sum = [1, 2, 3, 4].reduce((acc, x) => acc + x, 0); // 10
```

- Accumulates values into a **single result**.
    
- Can simulate **map, filter, every, some, even your own loop constructs**.
    
- Shape-shifter: you can build arrays, objects, or anything else.
    

**Nuance:**

- The `initialValue` is critical. If you don’t give one, `reduce` starts with the first element as `acc`.
    
    ```js
    [].reduce((a, b) => a + b); // TypeError
    ```
    
- You can write crazy elegant (or crazy unreadable) code with it.
    

---

### **5. `some` (the “at least one” checker)**

```js
[1, 2, 3].some(x => x > 2); // true
```

- Returns `true` if _any_ element matches.
    
- Short-circuits (stops at first truthy).
    

**Nuance:**

- Empty array always returns `false`.
    

---

### **6. `every` (the “all must obey” checker)**

```js
[2, 4, 6].every(x => x % 2 === 0); // true
```

- Returns `true` if **all elements** match condition.
    
- Short-circuits on first failure.
    

**Nuance:**

- Empty array returns `true` (the “vacuous truth” principle from logic).
    

---

### **7. `find` & `findIndex` (seekers)**

```js
const num = [5, 10, 15].find(x => x > 8); // 10
const idx = [5, 10, 15].findIndex(x => x > 8); // 1
```

- `find` returns first matching element.
    
- `findIndex` returns index of first match.
    
- If not found → returns `undefined` / `-1`.
    

---

### **8. `flat` & `flatMap` (dimension flatteners)**

```js
[1, [2, [3]]].flat(2); // [1, 2, 3]
[1, 2, 3].flatMap(x => [x, x * 2]); // [1, 2, 2, 4, 3, 6]
```

- `flat` removes nesting by given depth.
    
- `flatMap` = `map` + `flat(1)` in one pass (performance trick).
    

---

### **9. `includes` (the membership test)**

```js
[1, 2, 3].includes(2); // true
```

- Checks if value exists (unlike `indexOf`, works with `NaN`).
    

```js
[NaN].includes(NaN); // true
```

---

### **10. `sort` (the trickster)**

```js
[10, 1, 21].sort(); // [1, 10, 21] - lexicographic!
[10, 1, 21].sort((a, b) => a - b); // [1, 10, 21] - numeric
```

- Mutates the original array.
    
- Default is **string comparison**.
    
- Hidden performance details: uses an optimized **quicksort/Timsort hybrid**, not guaranteed stable pre-ES2019.
    

---

### **11. `reverse` (the backtracker)**

```js
[1, 2, 3].reverse(); // [3, 2, 1]
```

- Mutates the original.
    
- Handy with `sort`.
    

---

### **12. `concat`, `slice`, `splice` (structural helpers)**

- `concat`: merges arrays (non-mutating).
    
- `slice(start, end)`: extracts subarray (non-mutating).
    
- `splice(start, deleteCount, ...items)`: mutates—removes/insert elements.
    

---

## Why Array Helpers Matter

- They **hide iteration logic** → you write “intent” not “mechanics.”
- They’re **chainable** →
```js
const result = arr
    .filter(x => x > 5)
    .map(x => x * 2)
    .reduce((a, b) => a + b, 0);
```
- Cleaner, more expressive, less bug-prone than `for`.
- At scale, they make code **functional-style**, which is easier to reason about.
