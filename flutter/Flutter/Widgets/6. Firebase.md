
**Summary**
A short, practical cheat-sheet covering `get()` vs `snapshots()`, `DocumentSnapshot` / `QuerySnapshot` methods, subcollections and `Reference` behavior. Concise code examples and common pitfalls.

---

## Basics

* Firestore is lazy: references point to paths; no network traffic until you call `.get()` or `.snapshots()`.
* Use `.id` for document identity, `.reference.path` for a readable path string.

---

## `get()` vs `snapshots()` (return types)

* `get()`

  * `DocumentReference.get()` → `Future<DocumentSnapshot>`
  * `CollectionReference/Query.get()` → `Future<QuerySnapshot>`
  * One-time fetch (await and done)

* `snapshots()`

  * `DocumentReference.snapshots()` → `Stream<DocumentSnapshot>`
  * `CollectionReference/Query.snapshots()` → `Stream<QuerySnapshot>`
  * Real-time updates (continuous stream)

---

## `DocumentSnapshot` (common methods / fields)

* `data()` → `Map<String, dynamic>?` (null if document doesn't exist)
* `get(String field)` → `dynamic` (throws if field missing)
* `exists` → `bool`
* `id` → `String`
* `reference` → `DocumentReference`
* `metadata` → `SnapshotMetadata` (`isFromCache`, `hasPendingWrites`)

**Example**

```dart
final snap = await FirebaseFirestore.instance
  .collection('users')
  .doc('uid123')
  .get();
if (snap.exists) {
  final data = snap.data();
  final name = snap.get('name');
}
```

---

## `QuerySnapshot` (common methods / fields)

* `docs` → `List<QueryDocumentSnapshot>` (each has `.data()`, `.id`, `.reference`)
* `size` → `int`
* `docChanges` → `List<DocumentChange>` (useful in streams for diffs)
* `metadata` → `SnapshotMetadata`

**Example**

```dart
final qSnap = await FirebaseFirestore.instance
  .collection('posts')
  .where('published', isEqualTo: true)
  .get();
for (var doc in qSnap.docs) {
  print(doc.id); // use id or reference
}
```

## Subcollections & references

* `DocumentSnapshot` does **not** include subcollections automatically.
* To access: `docSnap.reference.collection('comments')` → **returns a `CollectionReference`**. No reads yet.
* Fetch subcollection explicitly: `.get()` or `.snapshots()` on that collection reference.

**Example**

```dart
final commentsRef = docSnap.reference.collection('comments');
final commentsSnap = await commentsRef.get();
```

---

## About `reference` string / `toString()`

* `DocumentReference.toString()` may look like a hashcode/memory string — it's an object.
* Use `reference.path` for stable readable path (e.g. `users/user123/posts/post456`).
* **Do not** store `toString()` output for identity; use `.path` or `.id`.

---

## Tips & Gotchas

* Billing: implicit fetching of subcollections never happens — good for costs. But be explicit about reads.
* `get()` errors on missing fields when using `get('field')` — prefer null-safe `data()?['field']` if optional.
* Use `docChanges` in streams to implement efficient UI updates (insert/modify/remove) instead of rebuilding entire lists.
* Check `metadata.isFromCache` when showing offline states.
