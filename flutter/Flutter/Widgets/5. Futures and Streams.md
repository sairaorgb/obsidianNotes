
## Overview

A Future represents a *single* asynchronous result; a Stream represents a *timeline* of events. Think of Future as a one-time snapshot and Stream as a live feed. Use Futures for one-shot work (API calls, single DB read) and Streams for continuous updates (timers, sockets, Firestore snapshots, sensors).

---

# Futures

## Mental model

* **Promise of a value** that will arrive later (success or error).
* States: uncompleted → completed (data) or completed (error).
* `async` marks functions that can await; `await` pauses that function until the Future resolves — **it does not block the event loop**.

## Practical notes

* `async` ≠ multithreading; it just yields the event loop.
* If you call a Future without `await`, the Future still runs; your function continues immediately (fire-and-forget).
* Cancelling a Future isn’t straightforward. You can ignore results or use token-based cancellation patterns.

## Pattern: one-shot UI fetch

```dart
FutureBuilder<User>(
  future: fetchUser(),
  builder: (c, s) {
    if (s.connectionState == ConnectionState.waiting) return Loading();
    if (s.hasError) return ErrorWidget(s.error);
    return ProfileView(user: s.data!);
  },
)
```

# Streams

## Mental model

* A **timeline** of events pushed to subscribers.
* Stream = events over time; you `listen()` and receive callbacks for every event.
* Streams can be **single-subscription** (default) or **broadcast** (many listeners).

## Key primitives

* `Stream<T>`: the readable event source.
* `StreamController<T>`: creates a `stream` and a `sink`. Use the sink to `add()` events and `close()` when done.
* `StreamSubscription<T>`: returned by `listen()`; call `.cancel()` to stop listening.

## Controller types

* `StreamController<T>()` — single-subscription; ideal for one consumer (sockets, UI-bound controllers).
* `StreamController<T>.broadcast()` — multiple listeners; useful for app-wide events or multiple widgets.

## StreamBuilder (UI glue)

* Subscribes to a Stream and rebuilds its subtree on events.
* `AsyncSnapshot` fields to watch: `connectionState`, `hasData`, `data`, `hasError`, `error`.
* Lifecycle: initial build (often `waiting`) → first event (`active`) → subsequent events (rebuilds) → optional `done`.

### Connection states

* `none`: no stream provided (`stream == null`).
* `waiting`: stream provided but no first event yet.
* `active`: stream has emitted at least one event (and may continue emitting).
* `done`: stream closed.

### Build counts to remember

* StreamBuilder always runs once initially.
* Then once per event. Example: 10 events → 11 builds (1 initial + 10 events).

## Common stream sources

* `Stream.periodic()` for timers
* `File.openRead()` for file streams
* WebSocket sockets / TCP sockets
* Firestore `.snapshots()`
* UI/input event controllers (text changes with `EventTransformer` or custom controllers)

# Patterns & Recipes

## 1) Simple timer

```dart
final timerStream = Stream.periodic(Duration(seconds: 1), (i) => i);

StreamBuilder<int>(
  stream: timerStream,
  builder: (c, s) => Text('Seconds: ${s.data ?? 0}'),
)
```

## 2) Manual counter with StreamController (dispose correctly)

```dart
class CounterWidgetState extends State<CounterWidget> {
  final _controller = StreamController<int>();
  int _count = 0;

  void _inc() => _controller.sink.add(++_count);

  @override
  void dispose() {
    _controller.close();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        StreamBuilder<int>(
          stream: _controller.stream,
          builder: (c, s) => Text('Count: ${s.data ?? 0}'),
        ),
        ElevatedButton(onPressed: _inc, child: Text('Inc')),
      ],
    );
  }
}
```

## 3) Firestore-style live updates

* Use `snapshots()` in StreamBuilder for chat/list views.
* Handle `ConnectionState.waiting` and `snapshot.hasError` explicitly.
* Paginate or limit to avoid huge snapshot payloads.

# When *not* to use Streams

* You only need **one** value → use `Future` / `FutureBuilder` / `initState` + `setState`.
* For simple local state changes (slider, toggle) — use `setState`, `ValueNotifier`, `ChangeNotifier` or provider/state management.
* If managing lifecycle and cancellations is painful, prefer simpler primitives.

Reason: Streams add lifecycle & cancellation surface area. Use them only when the problem is inherently temporal.

---

# FutureBuilder vs StreamBuilder — quick checklist

* Multiple ongoing updates? → **StreamBuilder**
* Single asynchronous response? → **FutureBuilder**
* Need multiple widgets listening? → **broadcast stream**
* Simple local reactive state? → `ValueNotifier` / `setState`

---

# Common pitfalls & fixes

* **Forgetting to close controller** → memory leaks. Fix: always `close()` in `dispose()`.
* **Multiple listeners on single-subscription stream** → runtime error. Fix: use `.broadcast()` or create separate streams.
* **Ignoring initial build** → StreamBuilder runs once before data; include a loading/default UI.
* **Nesting many builders** → fragile code. Fix: lift state up or use state management.
* **Assuming `async` = parallel** → it doesn’t; use isolates for heavy CPU work.

---

# Best practices / Tips

* Prefer `StreamBuilder` only for UI-bound continuous sources; keep business logic out of the widget tree (use blocs/providers/controllers).
* Use `Stream.transform()` for lightweight mapping/filtering before UI.
* Cache / debounce high-frequency streams (text input, sensor streams) to avoid UI thrash.
* For multiple sequential asynchronous calls, prefer `async/await` chaining rather than nesting builders.
* When exposing streams from services, provide a `dispose()` or close mechanism.

# Cheatsheet: helper snippets

**Cancel a subscription**

```dart
final sub = stream.listen((v) {});
sub.cancel();
```

**Broadcast controller**

```dart
final ctrl = StreamController<T>.broadcast();
```

**Basic debounce** (example using Rx-like patterns — implement or use rxdart when needed)

```dart
// naive debounce via timer (illustrative)
Timer? _debounce;
void onChange(String s) {
  _debounce?.cancel();
  _debounce = Timer(Duration(milliseconds: 300), () => _controller.sink.add(s));
}
```

# Glossary

* **sink**: input of a controller (where you `add()` events).
* **stream**: output, where listeners subscribe.
* **subscription**: a listener object returned by `listen()`.
* **broadcast**: a stream that allows many listeners.
